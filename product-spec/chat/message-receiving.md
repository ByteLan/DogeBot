# 消息收取与恢复

## 设置与判定

入口：「设置 → 聊天 → 消息收取方式」。选择后即时生效、自动保存在当前设备；缺失或非法值回落「始终收取」。

| 模式 | 收取条件 |
| --- | --- |
| 始终收取（默认） | 已登录；切换工作区、隐藏或最小化后继续订阅 |
| 仅查看群聊时收取 | 已登录、选中群聊 Tab、主窗口可见且未最小化；其余时间暂停 |
| 从不自动收取 | 不建立 desktop 实时订阅；不因登录、切页、换群或窗口恢复自动读取，消息由用户手动刷新 |

原生可见性按 `isVisible() && !isMinimized()` 判断。仅失焦、切到其他软件或被遮挡不作为暂停条件。Windows/Linux 隐藏到托盘、macOS 最小化到 Dock 或关闭隐藏均可触发按需模式暂停；恢复后仍需群聊 Tab 被选中。始终收取不承诺休眠或断网期间保持连接。

## 仅手动刷新

「从不自动收取」内部值为 `manual`，界面显示「仅手动刷新」。先手动刷新群列表，再选择群；选择只显示内存缓存，没有缓存时提示刷新。会话刷新拉取主线及必要的群信息/成员名，并刷新已打开的话题；话题有独立刷新入口，打开话题本身不拉历史。

列表/历史的显式分页、点击加载图片和读取引用详情仍可按需请求；图片进入可视区不自动下载。发送、上传和撤回照常请求 API，保留引用/撤回所需的目标校验，但完成后不附带历史刷新。切换页面、窗口恢复、失焦再聚焦不产生自动查询或订阅。该档不执行下述自动恢复流程，切回其他模式才按原规则恢复。

## 暂停与恢复规则

1. 暂停取消 desktop SSE、重试、看门狗、自动刷新与聊天只读请求；清除失效 loading，阻止旧响应触发新查询。
2. 保留当前群、话题、草稿、引用、附件、阅读锚点，以及已经显示的历史页和实时消息。暂停不会将实时消息隐藏。已经提交的发送、上传、撤回继续完成，完成后的自动查询等恢复再执行。
3. 恢复先建立订阅，再重新核对账号、机器人归属、当前群和当前时间线；其他缓存群再次访问时才校准，不全量追赶所有历史。
4. 主线与话题分别维护待同步状态：在最新位置时拉最新页；阅读旧历史时保留位置，显示「消息可能有更新，查看最新」。未完成的话题首屏必须补回。
5. 最新页成功不代表旧缓存全部已核对，不将中间有缺口的历史直接拼接。引用、回复、撤回旧消息前按需核对目标；撤回状态不能被晚到的历史响应覆盖。
6. 真正退出登录或切换服务端/凭证时销毁整个聊天会话，取消全部会话任务，释放缓存和草稿。

SSE 没有事件重放日志；断线、暂停后必须靠主动查询校准。SSE 失败但 REST 可用时允许手动刷新，并明确实时连接尚未恢复。

## 状态反馈

| 情况 | 用户反馈 |
| --- | --- |
| 策略暂停 | 中性「已暂停收取」，不误报网络故障，不自动重连 |
| 从不自动收取 | 「仅手动刷新」；手动查询时显示刷新进度，失败允许重试，不伪称实时同步 |
| 正在建连/校准 | 区分「正在连接」和「正在同步」 |
| 当前视图已校准且通道可用 | 「实时同步」 |
| 订阅或读取失败 | 连接/同步失败，保留阅读现场，提供刷新或重试 |

红点和新消息提示只表示当前进程观察到的更新，不是飞书个人账号的精确未读数。暂停期间没有实时新消息提示，不虚构数量。

desktop 暂停不会停止 server 的机器人长连接、命令、被动互动、cron、订阅通知或既有短期上下文。

验收关注：三模式下 Tab/显隐/失焦组合、手动模式初次进入和切群不读取、显式刷新/分页/图片可用、快速切换没有多条 SSE、暂停时读请求取消但写入完成、草稿保留、历史恢复不跳位、过期消息核对、401 释放会话。
