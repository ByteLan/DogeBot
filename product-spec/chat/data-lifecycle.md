# 聊天数据与内存缓存

## 数据来源与保存边界

- 飞书是聊天历史来源；server 按请求代理历史、详情、成员与图片，通过已有机器人长连接转发实时事件。
- server 聊天代理只合并在途读取，不保存已完成的历史响应、不建立消息数据库或 SSE 重放日志。历史读取不进入命令处理器，避免重放触发机器人业务。
- desktop 聊天消息、草稿、附件、引用、图片 Blob 和撤回免确认状态仅在 renderer 内存中保留，不写 localStorage、IndexedDB 或文件，也不提供离线入口。
- 登录 token、显示偏好、抖音配置等有各自的持久化规则。server 被动互动还存在独立的短期文字上下文与临时媒体文件，见[被动互动](../bot-interactions/passive.md)；不能把聊天代理无归档表述为整个 server 从不缓存内容。

## 容量规则

| 对象 | 当前预算/限制 |
| --- | --- |
| 已访问群 | 跨机器人合计最近访问的 10 个；以用户访问更新 LRU，后台事件不改变访问顺序 |
| 单群消息实体 | 主线、话题、引用详情合计最多 300 条；待发送动作另计，上限 3 个 |
| 消息正文估算预算 | 所有缓存群合计 16 MiB |
| 图片 Blob 预算 | 所有群合计 16 MiB，释放时撤销对应对象 URL |

预算用于限制聊天缓存，并非 Electron 进程的总内存上限。未访问群的实时事件不会自动创建完整历史缓存；超限按既有窗口裁剪/LRU 释放，之后可向飞书重新读取。会话被淘汰时草稿等会话内数据也可能释放，不承诺跨淘汰保留。

## 时间线一致性

- 主线分页固定首次查询的时间上界，续页携带原上界和游标；话题分页独立，并校验根消息归属。
- 按消息 ID 合并 HTTP 和 SSE，保持顺序、引用和撤回一致；旧请求不能覆盖新会话或复活已撤回消息。
- 阅读旧历史时不强行滚到底部；返回最新可重建最新窗口，不掩盖历史缺口。
- 隐藏到托盘和收取暂停保留内存；退出登录、重载 renderer、真正退出应用会清空。暂停规则见[消息收取](message-receiving.md)。

验收关注：LRU 跨 bot 淘汰、容量裁剪后可重新加载、图片释放、HTTP/SSE 乱序与撤回合并、账号切换释放及历史读取不触发命令。
