# 群聊审查修复与 Vitest 回归验证

状态：已实现，自动回归及构建验证通过。规格：[群聊](../../product-spec/chat/README.md)、[消息收取](../../product-spec/chat/message-receiving.md)、[数据生命周期](../../product-spec/chat/data-lifecycle.md)。

## 实施方案

1. 将暂停后的待同步状态与实际裁剪状态分开，保留暂停前已经展示的 HTTP/SSE 消息快照。
2. 消息和字节预算裁剪保留连续窗口。无法沿用原分页链时显式提供重新加载历史入口，不静默删除中间消息。
3. 主线和各话题分别维护编辑状态，发送、取消引用、撤回只清理相关目标；较早发送的完成回调不能清除后来选择的引用。
4. 草稿和待发送图片归属有界会话缓存，切群、关闭话题、暂停时保留，LRU 淘汰和退出时释放。图片预览 URL 仍随组件挂载释放。
5. 按用户要求采用 Vitest：迁移 desktop 19 项聊天验证、server 9 项聊天 API 验证和现有 HDR 测试；新增上述四项缺陷的回归，配置各应用的 `pnpm test`。

## 验证范围

运行环境：Linux、Node.js 24.21.0、pnpm 10.33.0、Vitest 5.0.5。

| 检查 | 结果 |
| --- | --- |
| 仓库根目录 `pnpm test` | 通过；依次调用两个独立应用的测试及测试/源码类型检查 |
| server Vitest | 13 项通过：迁移原 9 项聊天 API 场景和 4 项 HDR 测试 |
| desktop Vitest | 31 项通过：保留原 19 项验证，新增 7 项缓存回归和 5 项实际组件交互回归 |
| server `tsc -p tsconfig.json --noEmit` | 通过，部署入口继续为 `dist/src/index.js` |
| desktop `pnpm build` | 通过；保留原有大于 500 kB 的 bundle 提示 |
| 文档路径/链接、改动空白检查 | 通过 |

缓存回归覆盖暂停前主线/话题 HTTP 和 SSE 快照、暂停期间写入确认不拼接历史缺口、300 条与字节预算的连续裁剪、失效分页响应隔离、显式刷新后继续分页、定向撤回引用、附件预算及会话/话题 LRU 释放。

组件回归使用真实聊天组件和会话 hook，模拟 API 与 DOM，覆盖主线/话题独立取消引用和发送、迟到发送保留新引用、切群/切话题/关闭话题保留草稿和附件、切群后图片提交继续完成、旧话题发送完成不切走当前话题。预览 URL 在组件卸载时释放，File 由会话缓存持有；话题状态最多 10 个，待发送图片合计最多 16 MiB。

原 `scripts/verify-feishu-chat.ts` 已移除，单一 Vitest 入口取代独立运行器。server 测试使用临时 SQLite 数据库，显式关闭连接并清理目录，所有飞书请求均模拟；不启动长期运行的联调服务。desktop 的旧版 lockfile 6.0 随新增测试依赖迁移为 pnpm lockfile 9.0；未在仓库根目录安装依赖。

未验收：真实飞书租户、Windows/macOS 原生窗口和实际网络环境。当前结果是模拟 API/DOM 回归与 Linux 构建，不代表这些环境的端到端验证。
