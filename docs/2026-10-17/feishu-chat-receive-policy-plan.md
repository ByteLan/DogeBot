# 飞书群聊消息收取策略方案

当前行为与后续维护入口：[消息收取产品规格](../../product-spec/chat/message-receiving.md)。

后续第三档「从不自动收取」见[手动收取方案](feishu-chat-manual-receive-plan.md)；下文保留最初两档设计与验证记录。

日期：2026-10-17（北京时间）

状态：已在当前工作区实现，验证范围见第 8 节。实现前基线为 `b292ed1`。

关联：[飞书群聊工作台实现方案](../2026-10-16/feishu-desktop-chat-implementation-plan.md)。

## 1. 推荐决策

在「设置 → 聊天」增加「消息收取方式」，提供两个选项：

| 选项 | 内部值 | 行为 |
| --- | --- | --- |
| 始终收取 | `always` | 登录后持续订阅，切换工作区、最小化、隐藏到托盘后继续收取 |
| 仅查看群聊时收取 | `when-viewing` | 选中「群聊」Tab，且主窗口已显示、未最小化时收取；其余时间暂停 |

**设置默认值为「始终收取」，保持现有用户的行为；希望省资源时推荐选择「仅查看群聊时收取」。** 新装、升级和无效配置都使用相同默认值，不增加隐式迁移规则。用户选择后即时生效，只在当前设备保存偏好。

第一期在 desktop 控制订阅和查询生命周期，复用现有 REST 与 SSE，不修改 server 与飞书之间的长连接，不增加消息持久化或离线补录。暂不增加第三档、刷新频率滑块、系统通知或精确未读数。

## 2. 实现前行为与资源开销

| 接入点 | 基线实现 | 对方案的影响 |
| --- | --- | --- |
| [App.tsx](../../apps/desktop/src/renderer/App.tsx) | 登录后挂载聊天组件，Tab 切换使用 `hidden` | 离开群聊页不会停止订阅，甚至尚未打开群聊页时也会连接 |
| [use-chat.ts](../../apps/desktop/src/renderer/feishu/chat/use-chat.ts) | 校验 `/api/me` 后建立 SSE，监听 focus，处理自动刷新和重连 | 没有工作区或窗口可见性条件；需要集中控制所有自动读取入口 |
| [api.ts](../../apps/desktop/src/renderer/feishu/chat/api.ts) | 使用 fetch 流消费 SSE，带看门狗定时器 | 暂停必须取消流和定时器，不能只忽略收到的消息 |
| [cache.ts](../../apps/desktop/src/renderer/feishu/chat/cache.ts) | 已访问会话使用有界内存缓存；事件不会自动创建未访问会话的完整历史缓存 | 保留现有容量与 LRU 策略，不因收取模式扩大缓存 |
| [main-window.ts](../../apps/desktop/src/main/main-window.ts) | Windows/Linux 最小化与关闭隐藏到托盘，macOS 最小化到 Dock | 隐藏窗口仍保留 renderer，必须明确发布可见性变化 |
| [events.ts](../../apps/server/src/feishu/chat/events.ts)、[routes.ts](../../apps/server/src/feishu/chat/routes.ts) | 按用户即时分发事件，SSE 每 15 秒心跳；无消息事件重放日志 | 暂停后无法依靠 SSE 补发，恢复必须主动校准 |

现有通道不是周期性轮询全部历史；空闲时主要是连接与心跳，有事件时才传输消息。400ms 的 `message.refresh` 合并与 server 查询并发限制已经存在，但它们不控制页面离开后的收取。

本方案主要减少 desktop 与 server 之间的事件流量、事件解析、缓存变更和自动查询；不减少 server 为机器人业务接收飞书事件的必要工作。频繁恢复会产生最新页查询，因此不预先承诺具体节省比例，验收时观察真实请求数量。

## 3. 设置与可见性语义

### 3.1 设置界面

沿用 Arco `Card`、`Radio.Group` 与说明文字，与现有「自己发出的消息气泡」设置放在同一个「聊天」卡片中。

- 字段名：**消息收取方式**。
- 「始终收取」说明：切换页面或隐藏窗口后仍接收实时更新。
- 「仅查看群聊时收取」说明：离开群聊或隐藏窗口时暂停，返回后自动同步。暂停期间没有实时新消息提示。
- 自动保存，不增加「应用」「保存」按钮；切换无需二次确认。
- 暂停不影响已经提交的发送、上传或撤回操作，也不影响抖音监控。

偏好类型为 `ChatReceiveMode = 'always' | 'when-viewing'`，建议键名为 `dogebot.chatReceiveMode`。复用 `storage.ts` 的读取与持久化方式；未知值回落 `always`。此处只保存配置，不保存消息、草稿或图片。

### 3.2 判断条件

```ts
const viewingChat = workspaceView === 'chats' && windowVisible;
const receiveEnabled = loggedIn && (receiveMode === 'always' || viewingChat);
```

生产 Electron 客户端的 `windowVisible` 由主进程提供，统一定义为 `win.isVisible() && !win.isMinimized()`。本期不以 `focused` 或是否被其他窗口覆盖作为收取条件。

| 场景 | 始终收取 | 仅查看群聊时收取 |
| --- | --- | --- |
| 群聊 Tab，窗口正常显示 | 收取 | 收取 |
| 群聊 Tab，切到其他软件但窗口未隐藏/最小化 | 收取 | 收取 |
| 机器人、抖音监控或设置 Tab | 收取 | 暂停 |
| Windows/Linux 隐藏到托盘 | 收取 | 暂停 |
| macOS 最小化到 Dock，或关闭后隐藏 | 收取 | 暂停 |
| 托盘或 Dock 恢复窗口 | 维持连接，按需校准 | 仅当前 Tab 为群聊时恢复 |
| 退出登录、重载 renderer、真正退出程序 | 释放当前会话资源 | 释放当前会话资源 |

这里「始终」指登录会话存续且运行环境允许时持续订阅，不保证设备休眠或网络断开期间仍有连接。

原生桥不可用的浏览器预览环境可使用 `document.visibilityState` 与 `visibilitychange` 作为降级；Tab 是否选中仍单独判断。Electron 中采用原生状态，避免 macOS 遮挡检测与其他平台行为不一致。[Electron 页面可见性](https://www.electronjs.org/docs/latest/api/browser-window#page-visibility)说明了这些平台差异；原生判定参考 [isVisible](https://www.electronjs.org/docs/latest/api/base-window#winisvisible)、[isMinimized](https://www.electronjs.org/docs/latest/api/base-window#winisminimized)。

## 4. 暂停、恢复与页面交互

### 4.1 暂停

`receiveEnabled` 变为 `false` 时立即暂停，不增加延迟断开机制：

1. 取消当前 SSE 请求、连接重试等待、看门狗和消息刷新定时器。
2. 取消聊天只读请求，包括群列表、群信息、成员、历史、消息详情、图片下载；禁止新的自动读取与 focus 刷新。
3. 标记已缓存时间线需要重新校准，清理其 loading 状态，使被取消请求的晚到响应失效。
4. 保留聊天组件、选中的机器人和群、话题、主聊天和话题草稿、引用目标、滚动锚点及有界内存缓存。
5. 已经由用户提交的发送、图片上传和撤回继续完成；结果可写回同一登录会话的内存缓存。其完成回调引出的自动查询要等恢复后执行。

暂停期间不重新登录、不轮询历史、不自动扫描缓存群。现有进行中的写入可完成，但不因模式暂停自动重试写入。

### 4.2 恢复

`receiveEnabled` 变为 `true` 时执行一次恢复流程，快速重复切换时始终只保留一个有效连接周期：

1. 确认当前服务端与账号有效。401 仍执行退出流程；网络错误保留缓存，进入既有重连策略。
2. 先建立 SSE，再校准页面数据，减少查询和恢复订阅之间的消息空档。不要无限等待 SSE：连接失败时保留手动刷新能力，并明确提示实时连接未恢复。
3. 刷新机器人归属与当前机器人群列表，按需核对当前群是否仍可访问。群列表分页没有出现某个群不能作为退群依据；使用当前群查询与明确权限结果判断。网络失败不删除缓存。
4. 只自动校准当前会话与打开的话题，不批量回填其余缓存群；其他会话在再次访问时校准。
5. 消息按 ID、版本和撤回状态合并，复用现有请求 generation/revision 检查，避免查询覆盖查询期间到达的新事件。

每次暂停后的恢复都要校准，不能仅凭「距上次验证未超过 30 秒」跳过。相反，「始终收取」模式下普通切 Tab 不应重新连接或重复加载群列表。

### 4.3 阅读位置与历史缺口

| 恢复前的阅读状态 | 恢复行为 |
| --- | --- |
| 当前群在最新消息位置 | 拉取最新页并恢复实时展示 |
| 当前群正在阅读旧历史 | 保留锚点，提示「消息可能有更新，查看最新」；点击后重建最新窗口 |
| 话题已经打开且处于最新位置 | 独立校准话题最新页 |
| 话题正在阅读旧回复 | 保留位置，提供话题内「查看最新」入口 |
| 话题已打开但首屏请求在暂停时被取消 | 恢复后必须补首屏，不受主聊天正在阅读旧历史的状态影响 |

群主线和话题使用独立的待校准标记；主线成功不能提前清除话题的标记。查询失败的时间线保持待校准状态并提供重试。

最新页与缓存历史之间可能相隔大量消息。第一期不自动无限翻页追赶，不把缺少中间消息的两段时间线伪装成连续历史。保留现有「返回最新」和按需向上分页的方式；最新页成功仅说明该页已校准，不代表所有旧消息都完成核对。

暂停期间还可能发生修改、撤回、退群或机器人移除。旧缓存应标明待同步；旧历史上的引用、回复、撤回等依赖消息现状的操作先按需核对目标消息。不能因为某条消息不在最新页就判定其已撤回，也不后台逐条核对全部缓存。

### 4.4 状态与提示

连接状态与内容同步状态分开维护，避免「SSE 已连接」被显示成「历史已经补齐」。

| 状态 | 展示 | 行为 |
| --- | --- | --- |
| 按策略暂停 | 已暂停收取 | 中性色，不弹网络错误，不启动重连 |
| 正在建立订阅 | 正在连接 | 提示连接进度，不叠加重复 toast |
| 订阅已建立，当前时间线待校准 | 正在同步 | 当前缓存不能被表述为最新数据 |
| 订阅和当前时间线同步成功 | 实时同步 | 保留现有机器人连接状态提示 |
| 订阅或查询失败 | 连接失败 / 同步失败 | 保留阅读现场，允许刷新或重试 |

当前时间线没有待校准数据时不必制造「同步中」闪烁；打开群后再按需查询。群聊页面已有的状态位置承担反馈，不增加常驻全局横幅。

现有红点只表示当前进程观察到更新，不是飞书个人账号的精确未读数。暂停期间无法知道新增数量，不显示虚构计数；`activeKey` 也不能单独代表用户正在看消息，应结合 `viewingChat` 和时间线阅读状态判断是否提示新消息。

## 5. 实现拆分

### 5.1 窗口可见性

扩展 `DesktopWindowState`，增加 `visible: boolean`，沿用现有 `window:get-state` 与 `window:state-changed`，不暴露新的任意 IPC 能力。

- `main-window.ts` 在现有状态中计算 `visible`，补充 `show`、`hide`、`minimize`、`restore` 事件的发布；保留窗口来源校验。
- 主窗口加载完成时发布快照；状态读取不能被较旧的异步响应覆盖已收到的新事件。
- renderer 增加 `useWindowVisibility`，消费现有只读桥接；原生初始状态未知时，按需模式先不连接，避免启动瞬间误收取。
- `WindowChrome` 的初始值与类型、相关模拟桥接一起更新；保持 macOS 原生按钮和 Windows/Linux 托盘行为。
- 不为节流关闭 `backgroundThrottling`，也不通过窗口失焦模拟隐藏。

### 5.2 拆开三类生命周期

| 生命周期 | 拥有的数据/任务 | 结束条件 |
| --- | --- | --- |
| 登录会话 | API 实例、消息缓存、草稿、待发送状态、撤回免提醒状态 | 账号/服务端变化、退出登录、组件真正销毁 |
| 实时收取周期 | SSE、重试、看门狗、事件引发的延迟刷新 | 策略暂停或登录会话结束 |
| 单次请求 | 只读查询或用户提交的写入，各自有取消与超时 | 请求完成、对应操作取消或登录会话结束 |

不能直接在现有 SSE effect 中添加 `receiveEnabled` 依赖而保留原清理函数：当前清理会调用 `cache.clear()`，导致切 Tab 丢失消息和草稿。应将缓存销毁移到登录会话级清理，收取周期清理只结束自身任务。

基线的 `cache.dirty()` 会取消 `entry.controllers` 中的所有操作，而该集合还包含撤回、图片上传等任务。实现已保留会话级总请求登记，另加只读请求集合，并修改 `dirty()`：暂停只取消只读集合，真正销毁会话才取消全部任务。发送请求也受登录会话级取消约束，不受收取暂停约束。

所有自动入口使用同一个 `receiveEnabled` 条件，包括初始群列表、重连 ready、机器人连接恢复、消息刷新、focus 刷新、发送后话题刷新与图片观察器下载。已经发出的旧周期请求要有失效标记，暂停后的响应不能继续触发查询或将状态改回已连接。

区分账号鉴权通过、SSE 是否连通、内容是否校准三个状态。基线的 `ready` 和只按 API 实例创建的 `readyPromise` 不足以表达多次暂停/恢复；实现已按本次收取周期创建握手，避免第二次恢复误用已 resolve 的 promise。手动刷新不必依赖 SSE 成功，且不能偷偷恢复持续订阅。

## 6. 不做的扩展与后续选择

「后台轻量提醒」可作为以后第三档：在群聊页面收正文，在后台仅接收 `botId/chatId/有更新`。这能保留红点并减少后台正文流量，但需要 server 按每个客户端连接裁剪或合并事件、处理模式切换和撤回等变化；客户端收到正文后再丢弃不能节省网络流量。

当前目标用两档即可完成，第一期不引入这套额外协议。也不增加每隔若干秒轮询全群的方案，不把「暂停推送」实现为降低频率的持续历史抓取。

暂停只作用于 desktop；server 的飞书长连接、机器人命令、被动回复、定时任务、通知以及现有短期上下文机制按原逻辑运行。现有聊天历史无磁盘存储、无离线查看、无关键词搜索的边界继续生效。

## 7. 验证与验收

实施时使用现有类型检查、构建与最小验证脚本，不引入测试框架。模拟接口用于控制推送、延迟与乱序；Electron 实测窗口显隐，Windows/macOS 分别验证托盘与 Dock，不能用浏览器模拟结果代替原生结果。

| 场景 | 验收结果 |
| --- | --- |
| 无配置、损坏配置、已有配置 | 默认始终收取；有效选择刷新后保留；没有消息落盘 |
| 始终收取模式切换所有 Tab、隐藏和恢复 | 保持一条 SSE，不因切 Tab 重建订阅或重复查群列表 |
| 按需模式登录后停留机器人页 | 不建立聊天 SSE，不自动读取聊天群列表/历史 |
| 按需模式进入群聊、离开、再返回 | 进入订阅；离开取消且不重连；返回建立一条订阅并校准当前视图 |
| Windows/Linux 托盘、macOS Dock 与关闭隐藏 | 按需模式暂停，恢复时按当前 Tab 决定是否收取 |
| 仅窗口失焦、被其他应用覆盖 | 原生窗口未隐藏/最小化时不因失焦频繁断连 |
| 连续快速切 Tab 或设置 | 没有重复 SSE、遗留重试、看门狗或刷新请求；晚到响应无效 |
| 已缓存会话、主聊天/话题草稿、引用、图片附件 | 暂停和模式切换后仍保留现场；仅真正退出或既有淘汰条件释放 |
| 暂停时存在历史/成员/图片读取 | 请求取消、loading 解除、无误报网络错误，恢复可重新查询 |
| 暂停时发送/上传/撤回已提交 | 操作继续完成，无额外自动重试；完成后不引发后台查询 |
| 暂停期间有新消息、修改、撤回或机器人移除 | 恢复按需校准，旧缓存标明待同步，不伪造未读数或历史连续性 |
| 阅读旧主线/旧话题时恢复 | 不跳阅读位置；当前话题首屏若缺失则重新请求；各时间线标记独立 |
| SSE 连接失败但 REST 可用 | 展示连接失败，用户可刷新；不伪称实时同步成功 |
| 恢复期间再次暂停、换账号或换服务端 | 旧任务不污染新会话；退出释放缓存和所有会话任务 |
| 401、权限失败、群列表不包含当前群、网络错误 | 区分退出、明确不可访问和临时失败，不因分页缺项或网络失败误删 |
| 策略暂停或 desktop 真正退出 | server 机器人命令、通知和飞书长连接仍正常 |

## 8. 实现与验证记录

实现采用上述两个模式、默认值和原生窗口可见性语义，复用既有 SSE 与 REST 协议。server 无运行代码变更。`api.ts` 原有流取消及看门狗释放逻辑可继续使用；聊天查询、图片读取、发送和撤回按各自生命周期登记。

旧消息使用有界 `unverifiedIds` 标记等待核对；最新页校准不把全部旧缓存标记为已验证。引用、话题与撤回前按需核对目标，详情响应与同期撤回事件合并后使用缓存中的有效版本，防止较晚响应建立失效引用。

已通过 desktop 的 `pnpm build`（主进程与 renderer 类型检查、Vite 打包），以及 `node --import tsx scripts/verify-feishu-chat.ts` 的 19 项验证。新增缓存检查覆盖只读取消、晚到页失效、草稿与写入保留、主线和话题独立待同步、暂停期间确认发送结果、未选择会话时的查询释放。

模拟接口沿用 server 的独立临时数据库和假飞书响应，9 项 API 验证通过，不访问真实飞书租户。交互测试覆盖 Tab/收取模式切换、窗口显隐、暂停期间的新消息与撤回、在途发送/图片上传/撤回、长列表与历史阅读位置、SSE 失败下的手动刷新、配置持久化和窄窗口布局。恢复时的布局滚动不会将最新视图误判为历史阅读状态。

补充边界验证通过：主聊天阅读旧历史时补回话题首屏；未验证的旧消息在引用前核对；晚到详情不能覆盖撤回事件；旧群的延迟权限失败不会清除新切换的会话；恢复校验返回 401 时退出并释放旧会话。浏览器模拟场景未出现未处理的 renderer 异常。

在 WSLg 的 Linux Electron 34.5.8 中验证了实际 preload、原生 `hide`/`showInactive`、最小化/关闭隐藏到托盘及恢复、失焦保持收取、草稿保留与设置布局。Windows/macOS 的原生托盘、Dock 与实际飞书租户联调仍需在对应环境完成。
