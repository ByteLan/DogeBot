# 群聊「从不自动收取」方案

日期：2026-10-17（北京时间）

状态：已在当前工作区实现，验证范围见文末。基线：`c3abe6a`。产品规格入口：[消息收取](../../product-spec/chat/message-receiving.md)、[设备设置](../../product-spec/desktop/settings.md)。

## 决策与边界

消息收取新增第三档「从不自动收取」，内部值 `manual`，页面状态显示「仅手动刷新」。默认仍为 `always`，沿用设备本地偏好键，不迁移已有选择。

- desktop 不连接 `/api/feishu/chat-events`（现有通道是 SSE，并非 desktop WebSocket），也不进行聊天鉴权重试、轮询、focus 自动刷新或窗口恢复同步。
- 登录、切 Tab、切换 bot/群、恢复窗口均不自动拉群列表、历史、成员或图片。手动刷新群列表后可选择群，选择只显示已有内存缓存；没有缓存时提示刷新。
- 点击会话刷新时拉取当前主线、群信息和必要的成员名，若打开话题则同时刷新；话题提供独立刷新入口。话题打开只切换视图，不自动拉取其历史。
- 「加载更多群」「加载更早消息」属于显式分页；点击图片、引用原文、引用回复所需的单条校验属于显式按需读取，不启动后续自动同步。
- 发送、图片上传和撤回正常执行，结果写回当前内存缓存；写入完成不自动拉取话题或其他消息。引用/撤回仍须校验目标，不能为节流省略权限与撤回状态检查。
- 切入本档立即取消旧订阅、重试、延迟刷新和在途只读请求；保留缓存、草稿、附件及已提交的写入。切回原两档后按既有条件恢复收取和校准。
- server 飞书长连接、机器人命令、通知和定时任务不受影响。没有精确未读数，不把手动刷新结果显示成实时同步。

## 实现范围

1. 扩展收取类型、偏好读取和 Arco 单选设置，修正 App 的开启判定，保证 `manual` 不能因群聊正在显示而意外连接。
2. `useChat` 区分可手动操作与实时已就绪；允许手动列表/分页及缓存会话选择，禁止选择时的隐式读取；复用原有取消和缓存机制。
3. 图片观察器在本档不请求资源；按钮点击可读取。群列表、空时间线和话题给出可操作的手动刷新提示。
4. 更新产品规格、desktop README 与关联方案导航，不变更 server 协议或构建产物路径。

## 验收

- 初次配置/重载、切群、切 Tab、focus、隐藏/显示均无聊天 SSE、自动历史/详情/图片查询，手动按钮可以工作。
- 手动群列表与分页、会话/话题刷新、历史分页、图片点击、引用校验、发送和撤回可用，无附带自动同步。
- 从实时切入手动可取消延迟读请求、保留草稿和写入；切回原两档仍只保留一条订阅，默认值与非法配置回退不变。
- desktop 构建、既有缓存验证与模拟接口交互验证；真实飞书及 Windows/macOS 原生平台验收单独标记。

## 实现与验证记录

- desktop `pnpm build` 通过，包含 main/renderer 类型检查、Vite 打包与 preload 复制。没有 server 运行代码或产物路径变更。
- 原有 desktop 验证脚本的 19 项缓存、竞态、分页与 SSE 检查通过；server 临时数据库/模拟飞书接口的 9 项检查通过，不访问真实租户。
- 9 组浏览器交互检查通过：手动模式登录及页面/窗口变化无自动读请求；列表刷新和无查询的切群；消息/成员刷新与图片点击；列表/历史分页；话题打开与独立/同时刷新；发送/话题回复/撤回/引用校验；实时转手动时只取消读取、保留写入和草稿；原有两档及 640px 布局、偏好持久化；非法配置回退与手动请求 401 退出。没有未处理的 renderer 异常。
- WSLg/Linux Electron 34.5.8 实际 preload、窗口 hide/show、显式列表/历史刷新和 640px 设置布局验证通过。真实飞书及 Windows/macOS 原生平台未在本轮实测。
- 暂停/模式切换后，旧时间线仍可能有缺口；在途发送确认结果保存在缓存并更新摘要，不强行跳转旧阅读位置。用户刷新后重建最新窗口，不把“写入已完成”混同于“全部历史已同步”。
